# COS 云存储：家庭共账 / 个人备份 — 可行性方案分析

> 项目：墨麒麟记账（InkQilin Ledger）  
> 状态：方案分析（未实现）  
> 范围：评估「对象存储」能否支撑 **个人数据备份** 与 **家庭共享账本**

---

## 1. 背景与目标

当前应用以 **本地 Room 数据库** 为主：

- 基础版强调隐私，数据不出设备  
- 智能版可调外部 AI API，但账单本体仍以本地为准  
- 已有 Excel 导入导出、更新检测（Gitee）等能力  

在此之上，用户可能需要：

| 场景 | 诉求 | 优先级建议 |
|------|------|------------|
| **个人备份** | 换机、防丢、多端只读查看 | 更易落地，MVP 优先 |
| **家庭共账** | 多人记同一本账、实时/准实时可见 | 复杂度高，需单独设计 |

COS / OSS / 七牛 / R2 等对象存储均可承载「文件」类备份；是否适合「共账」取决于同步模型，而不只是能否传文件。

---

## 2. 结论摘要（先看这里）

| 维度 | 个人备份 | 家庭共账 |
|------|----------|----------|
| **技术可行性** | **高**。导出 SQLite/JSON/加密包 → 上传；恢复时下载导入 | **中低（直传 COS）**；**中高（COS + 轻后端/云函数）** |
| **产品可行性** | 高，用户预期清晰 | 中，需处理权限、冲突、时钟、隐私 |
| **成本** | 极低（个人级流量/存储几乎可忽略） | 低～中，取决于家庭规模与同步频率 |
| **安全风险** | 中（云上财务数据） | 高（多成员权限与密钥管理） |
| **MVP 建议** | **可做**：加密整库备份 + 版本列表 + 一键恢复 | **不建议**用「仅 COS 裸文件」做实时共账；应走「本地优先 + 服务端合并」或专用后端 |

**一句话**：  
- **个人备份**：适合 COS，建议 **客户端加密 + 私有读写桶 + 仅本机持有密钥**。  
- **家庭共账**：COS 只适合当「存档/附件/快照」层；真正共账需要 **鉴权、合并策略、变更日志**，更接近「极简同步服务」而不是「网盘」。

---

## 3. 方案拆解

### 3.1 方案 A — 个人备份（推荐 MVP）

**模型**：单用户、单设备为主，云上只存备份对象。

```text
[Android App]
   │ 1. 导出加密包 (.iqbackup / zip+aes)
   │ 2. PUT 到 COS（私有桶）
   ▼
[COS Bucket]  backups/{deviceOrUser}/{timestamp}.iqbackup
   │
   │ 列表 / 下载 / 恢复
   ▼
[同一或新设备] 导入覆盖/合并
```

**备份内容可选：**

1. **整库文件**：直接拷贝 Room 的 SQLite（实现简单，恢复快）  
2. **逻辑导出 JSON**：跨版本更稳，便于迁移与选择性恢复  
3. **附件分包**：相册/图片走单独前缀，账本包保持轻量  

**推荐形态**：`meta.json` + `ledger.enc`（或 zip 内含 db + assets），整体 AES-GCM 加密。

**优点**

- 不改变现有「本地优先」产品定位  
- 不需要账号体系也能做（用「备份口令 / 恢复码」派生密钥）  
- COS 只当对象桶，几乎无业务耦合  

**缺点 / 风险**

- 口令丢失 = 备份不可恢复（需明确提示）  
- 多设备若都上传，需「以哪份为准」的产品规则（最近成功备份 / 手动选择）  
- 换包名、升级数据库版本时，恢复需做兼容  

**访问控制建议**

- 桶：**私有读写**，不要公有读（财务数据）  
- App 内 **不要写死永久 AK/SK**  
- 可选路径：
  - **A1 轻后端**：自建/云函数签发 **预签名 URL**（PUT/GET，短时效）  
  - **A2 受限密钥**：单独子账号，仅该桶前缀读写（仍不推荐进 APK 明文）  
  - **A3 用户自带**：高级设置里填密钥（面向极客，风险自担）  

**MVP 最小闭环**

1. 设置 → 云备份：配置存储（域名/桶前缀 + 鉴权方式）  
2. 「立即备份」→ 进度 → 列表显示 N 个版本  
3. 「恢复」→ 二次确认 → 重启进入导入流程  
4. 本地保留最近 1～3 次备份校验信息（大小、时间、哈希）

### 3.2 方案 B — 家庭共账（需架构升级）

**问题本质**：不是「传文件」，而是 **多写者的并发合并**。

裸 COS 文件模型的典型坑：

| 问题 | 说明 |
|------|------|
| 最后写赢 | A、B 各上传整库，后传覆盖先传，丢账 |
| 无冲突检测 | 无法感知对方已改同一笔 |
| 权限粗糙 | 桶级公有/私有，难做「家庭成员只读/可写」 |
| 无在线状态 | 谁在线、谁改了什么，COS 不管 |
| 时钟与乱序 | 设备时间不准导致版本错乱 |

**因此：COS 不宜作为家庭共账的「唯一真相源」，只宜作旁路。**

#### B1. 仅快照共享（弱「共账」）

- 定期把加密快照上传到家庭前缀 `family/{homeId}/snapshots/`  
- 成员下载最新快照 **只读查看** 或 **手动导入合并**  
- **适合**：对账、看汇总，**不适合**高频共同记账  

#### B2. 变更日志 + 客户端合并（中等）

```text
设备A/B → 上传 append-only 事件 JSONL（加密）→ COS
     ↓
定期下载对方事件 → 本地 CRDT/LWW 合并 → 再生成新快照
```

- 仍避免强中心写库，但需要 **幂等 ID、删除墓碑、时钟偏移策略**  
- 复杂度显著高于备份；家庭 2～3 人可试，再多易痛苦  

#### B3. COS + 轻后端 / 云函数（推荐家庭方向）

```text
[App] --HTTPS--> [鉴权 API / 云函数] --读写--> [COS 或轻量 DB]
                      │
                 成员表 / 邀请码 / 角色
```

- COS 存：附件、图片、导出归档  
- 真正账本同步：云函数 + 云数据库 / 或「主版本号 + 补丁」  
- 邀请家庭成员：分享码，服务端校验  

**这是「能用的家庭共账」，不是「纯 COS 网盘」能单独完成的。**

## 4. 安全与合规

| 项 | 建议 |
|----|------|
| 传输 | 仅 HTTPS |
| 静态加密 | 客户端 AES-GCM；密钥由口令 KDF（如 Argon2/scrypt/PBKDF2）派生，**默认不上传密钥** |
| 元数据 | 版本号、设备名可明文放 `meta.json`；金额分类尽量只在密文包内 |
| 密钥轮换 | 备份口令变更时写新版本，不覆盖旧包（或标注不可读） |
| 日志 | 不要把完整 URL 带 token 打到 Logcat |
| 合规 | 涉及家庭成员财务信息，需产品侧说明用途与删除方式 |

> 注意：财务数据上云会 **降低**「基础版纯本地」的隐私卖点。建议：  
> - 基础版默认关闭云备份入口或明确标「可选、端到端加密」  
> - 智能版可默认展示，但仍需用户主动开启

## 5. 成本粗估（COS 量级）

以个人备份为例（假设整包 20MB，每天 1 次，保留 7 个版本）：

| 项目 | 估算 |
|------|------|
| 存储 | 20MB × 7 ≈ 140MB，可忽略 |
| 请求 | 每天几次 PUT/GET，可忽略 |
| 流量 | 恢复时下载 20MB；日常几乎为 0 |

家庭共账若频繁同步整库，流量会明显上升；应改为 **增量事件** 或 **低频快照**。

COS **公有读** 仍可能被刷流量；备份务必 **私有桶 + 预签名 URL**，并在费用中心设告警（与之前 APK 分发结论一致，但备份对私有要求更高）。

## 6. 技术选型对比

| 路线 | 备份 | 家庭共账 | 说明 |
|------|------|----------|------|
| 腾讯云 COS | 很适合 | 仅附件/快照 | 国内访问稳；APK 分发有限制，**数据库/JSON 备份无此限制** |
| 阿里云 OSS | 同上 | 同上 | 与 COS 同类 |
| WebDAV（坚果云等） | 适合 | 弱 | 用户自带网盘，隐私模型不同 |
| 自建 Nextcloud | 适合 | 中 | 可控但运维成本高 |
| Firebase/Supabase | 可 | 较适合 | 海外链路与合规需评估 |
| 纯本地 + 手动导出 | 现状 | 无 | 已有 Excel，缺「一键云恢复」 |

## 7. 推荐路线图

### 阶段 0：明确产品边界（文档/讨论）

- [ ] 确认是否保持「基础版不出网」原则  
- [ ] 备份格式：整库 vs JSON vs 双轨  
- [ ] 鉴权：预签名服务 / 用户自带密钥 / 暂不做云  

### 阶段 1：个人备份 MVP（建议 1～2 周量级）

- [ ] 设置「数据管理」增加一行入口 → `CloudBackupScreen`（见 §9）  
- [ ] `BackupExporter`：打包 + 加密 + 哈希  
- [ ] `BackupRepository`：列表 / 上传 / 下载 / 删除（接口化，便于换后端）  
- [ ] 状态卡 + 立即备份 + 历史列表 + BottomSheet 详情  
- [ ] 恢复二次确认 + 失败回滚  
- [ ] 存储配置二级页（预签名 API 或本地导出兜底）  
- [ ] 单元测试：加密往返、损坏包拒绝、空桶列表  

### 阶段 2：体验增强

- [ ] 自动备份（仅 Wi-Fi、每日/每周）  
- [ ] 多版本时间线、释放旧版本  
- [ ] 恢复到「新设备引导」流程  
- [ ] 导出校验页（哈希、条数摘要）  

### 阶段 3：家庭（可选，单独立项）

- [ ] 家庭 ID / 邀请码 / 角色（owner、member、viewer）  
- [ ] 事件日志或服务端合并，**不要**直接多写整库文件  
- [ ] 冲突策略：LWW 按字段、或「同笔双记提示合并」  
- [ ] 审计：谁在何时导入/修改（至少本地日志）

## 8. 风险清单

| 风险 | 等级 | 缓解 |
|------|------|------|
| 密钥/口令丢失导致无法恢复 | 高 | 恢复码展示一次、可选助记词；明确不可找回 |
| APK 内嵌云密钥被逆向 | 高 | 永不内置长期 AK；用预签名或用户配置 |
| 误恢复覆盖当前账本 | 高 | 恢复前强制确认 + 本地临时快照 |
| 数据库 schema 升级后旧包无法恢复 | 中 | 备份带 `schemaVersion`，恢复时迁移或提示升级 App |
| 家庭同步丢账 | 高 | 禁止「整库覆盖式」多写；上事件日志/服务端 |
| 云费用异常 | 中 | 私有桶 + 告警；不公有读 |
| 与「隐私本地」定位冲突 | 中 | 功能可选、文案透明、端到端加密 |

## 9. UI / 信息架构设计（针对「设置已经很挤」）

### 9.1 设计原则

| 原则 | 做法 |
|------|------|
| **不堆设置项** | 设置页只留 **1 个入口**，不把备份/家庭拆成又一个超长折叠区 |
| **与现有一致** | 复用 `SettingsSectionHeader` + `Card` + `ListItem` + 独立导航页（同 AI 配置 / OCR 配置） |
| **数据管理收口** | 云备份归入已有 **「数据管理」**，语义一致（导入导出都是数据） |
| **危险操作分层** | 「恢复覆盖本地」必须二级确认，不与「备份」并排弱化风险 |
| **基础版克制** | 入口文案强调「可选加密备份」，避免看起来像「必须上云」 |
| **家庭后置** | 家庭共账不进 MVP 设置；若立项走「功能开关」或独立 Tab，避免和备份混屏 |

### 9.2 入口放在哪（推荐唯一方案）

**设置 → 数据管理 → 云备份（推荐）** → `CloudBackupScreen`

```text
设置
├─ 应用版本
├─ 桌面小组件
├─ 显示设置
├─ 分类管理
├─ 功能开关          ← 人情账本等（家庭将来可挂这里）
├─ 多币种管理
├─ 更新检测
├─ 实验室功能
└─ 数据管理
     ├─ Excel 导入 / 导出 / 模板     （已有）
     ├─ 联系人导出等                （已有）
     └─ ★ 云备份（推荐）             ← 新增唯一入口
            └─ navigate("cloud_backup")
```

**不推荐：**

- 在设置顶层再开「云备份」大折叠区（会与更新检测、实验室、数据管理叠成第三堵墙）  
- 首页底部导航加 Tab（家庭才可能考虑，个人备份过重）  
- 把「立即备份」直接塞进现有数据管理每一行列表（缺少进度、列表、恢复上下文）  

### 9.3 设置页入口（一行）

与现有 `ListItem` 风格一致，只占数据管理区 **一行**：

| 字段 | 文案 |
|------|------|
| 标题 | 云备份 |
| 副标题 | 未配置时：`加密备份到对象存储，换机可恢复`<br>已配置且有最近成功：`上次备份 2026-09-12 · 18.4 MB` |
| 图标 | `Icons.Default.CloudUpload`（若无则 `Backup` / `ArrowUpward`，避免再踩 `Folder` 这种 extended 图标坑） |
| 点击 | 进入 `CloudBackupScreen` |

**可选增强（设置行右侧）：** 小字状态 Chip：`已关闭` / `已配置` / `需登录`。仍不展开子项。

### 9.4 CloudBackupScreen（MVP 主界面）

单页纵向滚动，顶部标题栏「云备份」，结构自上而下：

```text
┌─────────────────────────────────────────┐
│  云备份                              ?  │  ← 帮助/说明弹窗
├─────────────────────────────────────────┤
│  [状态卡]                                │
│  存储：腾讯云 COS                        │
│  状态：未配置 / 就绪 / 备份中 45%        │
│  上次成功：2026-09-12 10:20 · 18.4 MB    │
│  [ 立即备份 ]  [ 刷新列表 ]              │
├─────────────────────────────────────────┤
│  备份历史                                │
│  ┌───────────────────────────────────┐  │
│  │ 今天 10:20   18.4 MB   设备A   ›  │  │
│  │ 09-10 22:01  18.1 MB   设备A   ›  │  │
│  │ 09-01 08:00  17.9 MB   设备B   ›  │  │
│  └───────────────────────────────────┘  │
│  （空态：还没有云备份，点「立即备份」）  │
├─────────────────────────────────────────┤
│  存储配置                     未配置 ›   │  → 子页或底部弹层
├─────────────────────────────────────────┤
│  自动备份  [关闭 ▾]                      │  → 关 / 每日 / 每周（MVP 可后置）
└─────────────────────────────────────────┘
```

**主操作区说明**

| 控件 | 行为 |
|------|------|
| 立即备份 | 走加密导出 → 上传；进行中显示 LinearProgress + 百分比；成功 Toast + 列表刷新 |
| 刷新列表 | 拉取远端 index/对象列表；失败显示行内错误条，不弹全屏 |
| 历史行 | 点击打开 **底部 ModalBottomSheet**（详情），不要一上来就恢复 |
| 存储配置 | 二级页/弹层，避免主屏被密钥输入污染 |

### 9.5 详情 BottomSheet（点某次备份）

```text
备份详情
时间：2026-09-12 10:20
大小：18.4 MB
设备：Pixel · Android 14
摘要：账单 1,203 条 · 分类 28 · 资产 12
校验：sha256 与 meta 一致 ✓

[ 下载并恢复 ]   [ 删除此备份 ]
取消
```

- **下载并恢复** → 确认对话框（见下）  
- **删除此备份** → 危险色 + 二次确认  

### 9.6 恢复确认对话框（强制）

标题：`恢复将覆盖当前账本`  

正文要点（短句，避免论文）：

- 当前本地数据会被备份包内容 **替换**  
- 建议先「另存本地导出」  
- 口令错误则无法解开备份  

按钮：`取消` | `我明白，恢复`（强调色，不默认负向焦点）

### 9.7 存储配置（二级）

MVP 只做一种清晰路径，避免「一屏八种云厂商」：

**模式选择（分段控件或单选列表）**

1. **预签名接口（推荐，若你有云函数）** — 只填 API Base URL  
2. **自定义 S3 兼容** — Endpoint / 桶 / 区域 / 临时 AK（高级，折叠「高级选项」）  
3. **仅本地加密导出（无云）** — 密钥在本机，导出到系统文件选择器（隐私版兜底）  

界面原则：

- 敏感输入 `PasswordVisualTransformation`  
- 「测试连接」按钮，成功/失败行内反馈  
- 说明文案固定一句：`账本在上传前加密，密钥由备份口令派生，默认不上传`  

### 9.8 备份口令（首次备份/首次恢复）

用 **Dialog 或独立全屏**，不要嵌在列表里：

```text
设置备份口令
  口令 ********
  确认口令 ********
  [ ] 我已理解：忘记口令将无法恢复

提示：建议 8 位以上，可写在密码管理器

[ 取消 ]  [ 生成恢复码并继续 ]
```

- 成功后展示 **一次性恢复码**（全屏，强制用户点「我已保存」）  
- 之后备份复用已存口令派生的密钥材料（Android Keystore 包一层，口令本身不落明文盘）  

### 9.9 自动备份（MVP+，可隐藏）

主屏底部一行即可，**默认关闭**：

| 模式 | 触发 |
|------|------|
| 关闭 | 仅手动 |
| 每日 | 充电 + Wi-Fi 下后台（WorkManager） |
| 每周 | 同上 |

失败通知用现有 Notification 通道，不新开复杂通知中心。

### 9.10 家庭共账 UI（二期草图，勿与备份混做）

若立项，**不要**塞进云备份页。建议：

## 11. 最终建议

1. **个人备份：可行且值得做。** 用 COS 私有桶 + 客户端加密 + 预签名 URL（或后续再上云函数），先打通「备份 → 列表 → 恢复」。  
2. **UI：设置只加一行入口**，全部复杂度沉到 `CloudBackupScreen`，避免设置页继续膨胀。  
3. **家庭共账：不要把 COS 当同步数据库。** UI 与备份彻底拆分；先备份 MVP。  
4. **隐私叙事：** 显式可选、端到端加密、密钥默认仅在用户侧。  
5. **与更新分发区分开：** 更新包可半公开；**账本备份必须私有**。
